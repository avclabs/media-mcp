## 选定候选 2，grilling 第一批决策（均已确认）

**更正上一节的一处判断**：`uploadImageToTos` 的问题不是「缺 base64 回退」，而是它**硬编码**了
`sigData.policy` 这一种字段命名约定；enhance 那份走通用重命名循环因而更宽容。两侧无共享宽容逻辑。
upstream 实际返回哪种形态**未验证**（无 API key），设计不得依赖该假设。

**两个签名协议的真实差异（5 处）** —— 这是 seam 成立的依据：
1. endpoint `/api/v3/contents/generations/tos-signature` vs `/get_postsignature_url`
2. auth `Authorization: Bearer` vs `X-API-Key`
3. 字段命名 `origin_policy`+无前缀 vs `policy`+`x-tos-` 前缀
4. `key` 推导：上传 URL pathname vs `policy.conditions[].key`
5. 响应码判定：认 `0 || 200` vs 只认 `0`

而 `file_id` 推导两侧**规则相同**（上传 URL pathname 末段），不进 adapter。

**已确认的决策**
- **Q1=A** seam 形状：`prepareUpload(fileName) → { uploadUrl, formFields }`。fileId 与表单提交归 upload module。
- **Q2=A** 上传体：`body: Buffer | Readable`（form-data 两者都吃）；interface 上要写明「有 path 就用 stream，别 readFileSync」。
- **Q3=A** 宽容度归 upload module 公共能力：`normalizeSignatureFields(raw) → formFields`，两个 adapter 在 implementation 里调用（不撑大 adapter interface）。
- **Q4=A** 范围：只做 upload 这一层。image/video 的两份副本合成一份共用 upload module，SAM3 切为第二 adapter；
  **任务管线（createTask / polling / 响应整形）保持原样**，候选 1/3/4 留作后续单独一刀。
- **Q5=A** 先写 characterization test 再重构；测试框架用 Node 内置 `node:test`，零新依赖。

**查清的仓库约束（影响后续设计）**
- `README.md:119` 列出的 9 个 tool 名是文档化对外契约，不得改。
- `README.md:128-129` 文档化了 `SAM3_POLL_INTERVAL` / `SAM3_POLL_MAX_ATTEMPTS` —— 是公开配置，
  **候选 3 若要做 timeouts 统一，不能直接删掉这两个 env**。
- `package.json` `files: ["dist"]` → `dist/` 是发布物，测试产物不能落进去。
- `.npmignore` 有 `*.ts` 但随后 `!dist/*.d.ts` 取反 —— `dist/*.test.d.ts` 会被**包含**，别跟取反顺序打架。
- `.gitignore` 里 `test`（无斜杠）会吞掉任何名为 `test` 的目录 → 测试目录要用 `tests/`。
- `tsconfig.json`：`include: src/**/*`、`rootDir: src`、`outDir: dist`、`declaration: true`。
- Node 22.22.2 支持 `--experimental-strip-types`，但 `engines: >=18.0.0`，不能依赖它。

**grilling 第二批决策（均已确认）**
- **Q6=A2** adapter 的 transport 是窄接口 `{ post(path, payload): Promise<unknown> }`。
  分工：endpoint 是协议知识 → 归 adapter；host 与 auth 头是环境知识 → 归 transport。
- **Q7=A** 新模块单文件 `src/upload.ts`（module + adapter interface + normalizer + 两个 adapter，约 250 行）；
  超过 ~300 行再拆目录。
- **Q8=A** 测试放 `tests/*.test.ts` + 新增 `tsconfig.test.json`（`outDir: dist-test`、`declaration: false`），
  `npm test` = `tsc -p tsconfig.test.json && node --test "dist-test/tests/**/*.test.js"`；
  `dist-test/` 要加进 `.gitignore` 与 `.npmignore`。
- **Q9=A** 验收标准：enhance 路径要求与旧实现**逐字节等价**；SAM3 路径允许行为差异，
  但差异必须显式列进测试。
- **Q10=A** 建 `CONTEXT.md`。**已按仓库英文优先策略用英文撰写**（对应提交 `b6a1888`）。

**设计中发现的新 divergence（不要统一，要保留并标注）**
- `key` 来源不同：enhance 用 `decodeURIComponent(pathname.slice(1))`；SAM3 用 `policy.conditions[].key`。
  两者可能不等（非 ASCII 文件名时）。保留各自行为（Q9 要求），但登记为待用真实 API 核实的悬案。
- `file_id` 推导也有细微差：enhance 做了 `decodeURIComponent`，SAM3 没做。
  非 ASCII 文件名下 SAM3 会把 percent-encoded 串当 file_id 发出 —— 统一后行为会变，属「允许差异」，须进测试。

## 候选 2 已落地（2026-09-13）

**新模块 `src/upload.ts`（275 行）**
- seam A `SignatureTransport { post(path, payload) }`，生产实现 `createAxiosSignatureTransport({baseUrl, apiKey, auth:'bearer'|'x-api-key'})`
  —— 顺带补了 HTTP 4xx 的 `status=… data=…` 错误详情（旧 enhance 有、SAM3 没有）。

  `createEnhanceSignatureAdapter({transport, fileType})` / `createSam3SignatureAdapter({transport})`。

  `parseFileIdFromUrl`（percent-decoded）、`checkLocalFile`（100MB）、`encodePolicy`。

  `createMediaUploader` 预绑定成 `(body, fileName) => {fileId}`，`server.ts` 里为三个媒体类型各造一个。
