## 发布方式（实测核对）

- **形态**：产出一个 npm 包，不是部署服务。stdio MCP server 跑在用户机器上，通过 HTTPS 调
  `mcp.avc.ai/enhance` 与 `/sam`。
- **两条分发渠道**：
  1. npm registry `@avclabs.ai/media-mcp`（主渠道，用户 `npx -y ...@latest` 拉取）
  2. 官方 MCP Registry —— 靠 `server.json`（schema 2025-12-11）+ `package.json.mcpName = io.github.avclabs/media-mcp`
     关联，用 `mcp-publisher.exe` 发布；git 历史有 `ae69ef4 chore: update server.json for MCP registry publishing`。
     `.gitignore` 收了 `.mcpregister_github_token` / `.mcpregistry_*` / `MCP_REGISTRY_PUBLISH_GUIDE.md` / `mcp-publisher.exe`。
- README 另提到非 npm 渠道：GitHub release、私有 tarball、MCP 目录。
- **版本号 4 个文件 6 处**：`package.json`、`package-lock.json`（顶层 + `packages[""]`）、
  `server.json`（顶层 + `packages[0]`）、`src/server.ts` 的 `McpServer` metadata。
- **门禁** `npm run release:verify` = `check:release` + `npm audit --omit=dev --audit-level=high` + `npm test`(含 build) + `npm pack --dry-run`。
- **发布产物实测**（`npm pack --dry-run`）：25 个文件 / 29.6 kB tarball / 解包 130.7 kB，含 `dist/*.js` + `.d.ts` + **`.js.map`/`.d.ts.map`（约 36 kB，占解包体积 28%）**；`src/`、`docs/`、`tests/`、`scripts/` 均不入包。
- **registry 实测**：仅发布过 4 个版本 —— 0.1.0 / 0.1.1（2026-05-08）、0.2.0（2026-05-12）、0.2.1（2026-05-22），
  `latest = 0.2.1`，距今已 4 个月。0.2.1 的 `dist.fileCount = 17`，与候选版 25 的差 8 个正好是
  `service-config`(4) + `image-enhancement`(4) 的产物 → 证明 0.2.1 早于这两个文件，图片工具从未发布过。

### 发布链路上发现的实操问题
- **`git tag` 数量为 0**：`docs/RELEASE.md:50` 要求发布后 `git tag v<version>`，但仓库一个 tag 都没有 →
  0.2.1 那次发布没打 tag，发布不可回溯、也无法用于回滚定位。
- **无 CI**（无 `.github/`）：`release:verify` 全靠人记得跑。
- **本机 `npm config get registry` = `https://registry.npmmirror.com`（淘宝镜像），且 `package.json` 无 `publishConfig`** →
  照文档直接跑 `npm publish` 会打向镜像而非官方 registry。发布前必须显式指定
  `--registry https://registry.npmjs.org`。
- `package.json.mcpServer` 是自定义字段（非 npm 规范），构成第三份配置源，无同步门禁。

### 项目事实（长期）
- 版本号必须同步 **4 处**：`package.json` / `package-lock.json`（顶层 + `packages[""]`）/ `server.json`（顶层 + `packages[0]`）/ `src/server.ts` 的 `McpServer` metadata；门禁为 `npm run check:release`（`scripts/check-release.mjs`）。
- 发布顺序被强制：先后端 `/enhance` 图片路由 + `/sam/health` JSON health，再 Portal，**最后**才发 npm `0.3.0`（否则新客户端打空接口）。
- 构建产物在 `dist/`，`bin.media-mcp → dist/server.js`；`files` 白名单只发 `dist` + config + 文档。
- 日志必须走 `console.error`（stdout 是 JSON-RPC 通道）——现状正确，重构时勿破坏。
- 工具描述里用 `Use this tool ONLY for ...` + 中文关键词区分 enhance/colorize/denoise 三个易混工具，这是有效设计，保留。
